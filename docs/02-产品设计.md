# 02 · 产品设计 【提案】

## 执行链（产品的骨架）

```
① 信号        ② 选品分析        ③ listing 生成       ④ 洞察           ⑤ 建议
市场数据/      竞争密度/毛利     多平台格式+SEO       评论聚类         调价/广告
趋势输入  →    模型评分     →    图片brief+文案  →    差异点提炼  →    动作建议
                                    ↓人工闸门↓                            ↓人工闸门↓
                                  确认后 API 上架                      确认后执行
```

**设计铁律：涉及资金与平台写入的动作（上架、改价、开广告）一律过人工确认闸门**，
agent 负责准备与推进，不负责扣扳机（详见 03 合规边界）。

## 各段设计

### ① 信号（输入层）
- 内置源：平台公开榜单/类目趋势（合规范围内）、卖家授权的店铺数据（SP-API）；
- 外部输入：卖家自己丢进来的链接/关键词/直觉（"我觉得这个品要起"）。

### ② 选品分析（第一价值点）
- 每个候选品一张评分卡：竞争密度（头部评论数分布）、价格带、差评归因预判、
  毛利测算（含头程/FBA 费用速算）、风险标记（季节性/侵权词预扫）；
- 输出不是"告诉你卖什么"，是"把你想卖的判断变成立体依据"——尊重卖家的选品直觉，
  这是与"AI 选品大师"类骗感产品的本质区别。

### ③ listing 生成（最成熟段，做深度）
- Amazon：标题公式（关键词前置）、五点、A+ 内容 brief、后台 search terms；
- TikTok Shop：短视频脚本大纲 + 挂车文案（语感完全不同的两套语域）；
- Shopify：SEO 页面结构 + FAQ 预生成；
- **每平台独立评测集**（见 03），语域混用是 AI listing 的通病，是我们的第一个质量护城河。

### ④ 评论洞察
- 竞品差评聚类归因（结构：抱怨点→频率→可改进点→机会话术），
  产物直接回喂 ③ 的卖点排序——链路的自我闭环。

### ⑤ 建议（v0.1 只读）
- 调价/广告建议只生成工单，不自动执行；执行集成（v1）同样过闸门。

## 链路留痕（信任与差异化的产品表达）

- 每条链路一张时间线：agent 每步看了什么数据、做了什么判断、产出了什么——
  可回放、可导出。卖家审计 agent 的决策过程 = 工具链项目"run archive"思想的产品化移植；
- 失败/低置信步骤显式标黄，卖家可重跑单步。

## 明确不做（M0）

- 不做选品"答案机"（割韭菜产品形态，且做不到）；
- 不做自动跟卖/监控告警类灰色功能；
- 不做 ERP（订单库存是领星们的地盘）。
